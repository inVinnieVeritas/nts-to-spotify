# NTS to Spotify v0.1.1

Version 0.1.1 is a focused local-edition patch for more accurate review classification and more
readable Windows launcher failures. It contains no playlist synchronization protocol changes.

## What changed

- Spotify results no longer enter **Primary Review** solely because their title adds a supported
  trailing `Remaster` or `Remastered` qualifier. The artist and remaining base title must still
  satisfy the existing matching requirements.
- Meaningful alternatives such as live recordings, remixes, acoustic versions, edits, mono or
  stereo versions, and re-recordings remain distinct and reviewable.
- Saved unresolved catalogue entries are reclassified when displayed. Explicit inclusion,
  exclusion, and alternative-candidate choices are preserved, and saved catalogues do not need to
  be rescanned.
- When `setup-local.cmd` or `start-local.cmd` is opened by double-clicking in Windows Explorer, a
  startup failure remains visible and shows `Press any key to close this window.` The original
  failure exit code is preserved after the key press.
- Launches from an existing Command Prompt or PowerShell window, CI, redirected input, and
  successful startup continue without that pause.

## Windows upgrade procedure

1. Download and extract v0.1.1 into a new folder.
2. Stop the old server with `Ctrl+C`.
3. Copy the existing `.env` file into the new folder.
4. Copy the existing `.data` directory into the new folder if it exists.
5. Run `setup-local.cmd` in the new folder.
6. Start with `start-local.cmd`.
7. Open the same `http://127.0.0.1:5173/` address.
8. Confirm that saved catalogues and linked playlists remain available.
9. Keep the old installation until the new version is verified.

Browser catalogue progress is associated with the browser origin. Using the same scheme, host,
and port lets the same browser profile see its existing IndexedDB data. The `.data` directory is
separate installation-local server data containing the public Spotify match cache and cooldown
state. It does not contain browser catalogue progress.

Back up important catalogue progress before upgrading. Never share `.env`; it contains personal
Spotify application credentials. Progress backups may contain personal catalogue and review
choices and should also be stored accordingly.

## Compatibility

- No rescan is needed for existing catalogues.
- Existing linked playlists and resumable synchronization state remain compatible.
- Catalogue persistence, matcher, backup, and playlist synchronization protocol versions are
  unchanged.
- The local callback remains `http://127.0.0.1:5173/login`.
