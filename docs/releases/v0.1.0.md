# NTS to Spotify v0.1.0

NTS to Spotify turns the tracklist from one NTS episode—or a complete show archive—into a Spotify
playlist. It saves long catalogue scans locally, gives you review tools for uncertain matches,
and can safely update the same linked playlist when new episodes arrive.

## Highlights

- Import individual NTS episodes or full show catalogues.
- Resume catalogue scans and preserve reviewed track choices between sessions.
- Handle Spotify pacing, retries, and cooldowns without losing completed work.
- Cache public match results locally to avoid unnecessary repeat searches.
- Preview additions, removals, order, and metadata before updating Spotify.
- Deduplicate exact Spotify track URIs while preserving the selected chronology.
- Resume large ordered playlist updates with settlement and ambiguous-write safeguards.
- Back up and restore catalogue progress with portable JSON files.

## Windows installation

Node 24 LTS is recommended. Download the `v0.1.0` source ZIP from GitHub Releases, extract it into
a folder writable by your Windows account, and run `setup-local.cmd`. Add credentials from your
personal Spotify developer application to `.env`, then run `start-local.cmd`.

Register this exact Spotify callback URI:

`http://127.0.0.1:5173/login`

The local server listens only on `127.0.0.1:5173` by default. See the README for detailed setup,
Spotify application, backup, update, and troubleshooting instructions.

## Privacy and local data

Catalogue progress and review choices stay in the browser for this local origin. Public Spotify
match data is cached under the local installation's `.data` directory. Spotify tokens are held in
HTTP-only cookies, while credentials stay in the ignored `.env` file. Progress backups may contain
personal catalogue and review choices, so store them accordingly. Credentials, tokens, cookies,
and server cache data are excluded from catalogue backups.

## Platform limitations

Windows received real manual acceptance testing. Linux and macOS startup commands are documented,
but have not received equivalent manual platform testing. Install the application in a
user-writable directory. This release supports a private IPv4-loopback local server; public hosting
is outside its scope.

## Upgrading

Download catalogue backups before updating. Stop the server after active operations finish,
replace or update the source while preserving your `.env` and `.data`, run `npm ci` and
`npm run build`, then restart at the same host and port so the browser uses the same saved origin.
